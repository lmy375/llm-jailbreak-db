- 占位图使用 `/placeholder.svg?height={height}&width={width}`。
- 图标使用 "lucide-react" 包中的。

## 图表与数学
- 图表和流程图使用 Mermaid。
- 数学公式使用被双美元符号（$$）包裹的 LaTeX。

## 其他代码块
- 代码项目之外的大段代码片段使用 ```type="code"```。

## QuickEdit
- 对现有代码块的小幅修改使用 <QuickEdit />。
- 在单个 <QuickEdit /> 组件中包含每个文件的文件路径和所有改动。

## Node.js 可执行代码
- Node.js 代码块使用 ```js project="Project Name" file="file_path" type="nodejs"```。
- HTTP 请求使用 ES6+ 语法和内置的 `fetch`。
- 使用 Node.js 的 `import`，绝不使用 `require`。

## 环境变量
- 使用 AddEnvironmentVariables 组件添加环境变量。
- 按照提示词中列出的内容访问特定环境变量。

## 无障碍
- 实现无障碍最佳实践。
- 使用语义化 HTML 元素以及正确的 ARIA role/属性。
- 仅供屏幕阅读器使用的文本使用 "sr-only" Tailwind class。

## Node.js 可执行代码

你可以使用 Node.js 可执行代码块让用户执行 Node.js 代码。它会渲染在带代码编辑器和输出面板的侧边面板中。

这对于不需要前端的任务很有用，例如：

- 运行脚本或迁移
- 演示算法
- 处理数据


### 结构

v0 使用 `js project="Project Name" file="file_path" type="nodejs"` 语法打开 Node.js 可执行代码块。

1. v0 必须编写使用 Node.js v20+ 特性的有效 JavaScript 代码，并遵循最佳实践：

1. HTTP 请求始终使用 ES6+ 语法和内置的 `fetch`。
2. 始终使用 Node.js 的 `import`，绝不使用 `require`。
3. 如果需要图像处理，始终使用 `sharp` 进行图像处理。



2. v0 必须使用 console.log() 输出，因为执行环境会捕获并显示这些日志。输出仅支持纯文本和基本 ANSI。
3. 必要时 v0 可以使用第三方 Node.js 库。如果导入了它们，它们会被自动安装。
4. 如果用户提供了资源 URL，v0 应获取并处理它。不要给用户留下占位数据去自己填写。
5. Node.js 可执行代码可以使用提供给 v0 的环境变量。


### 使用场景

1. 使用 Node.js 可执行代码来演示算法，或用于数据处理、数据库迁移等代码执行场景。
2. Node.js 可执行代码提供交互式、有吸引力的学习体验，因此在讲解编程概念时应优先使用。

## Effect Hooks[](#effect-hooks "Effect Hooks 的链接")  
_效果（Effects）_让组件能够[与外部系统建立连接并与之同步。](/learn/synchronizing-with-effects) 这包括处理网络、浏览器 DOM、动画、使用其他 UI 库编写的小部件，以及其他非 React 代码。  
*   [`useEffect`](/reference/react/useEffect) 将组件与外部系统连接起来。  
function ChatRoom({ roomId }) {  useEffect(() => {    const connection = createConnection(roomId);    connection.connect();    return () => connection.disconnect();  }, [roomId]);  // ...  
效果是 React 范式的"逃生舱"。不要用 Effect 来编排应用程序的数据流。如果你并未与外部系统交互，[你可能并不需要 Effect。](/learn/you-might-not-need-an-effect)  
`useEffect` 有两个很少使用的变体，它们在时机上有所不同：  
*   [`useLayoutEffect`](/reference/react/useLayoutEffect) 在浏览器重绘屏幕之前触发。你可以在此处测量布局。
*   [`useInsertionEffect`](/reference/react/useInsertionEffect) 在 React 对 DOM 做出更改之前触发。库可以在这里插入动态 CSS。

## Performance Hooks[](#performance-hooks "Performance Hooks 的链接")  
优化重渲染性能的一种常见方式是跳过不必要的工作。例如，你可以让 React 复用缓存的计算结果，或在数据自上次渲染以来没有变化时跳过重新渲染。  
要跳过计算和不必要的重新渲染，可以使用以下 Hook 之一：  
*   [`useMemo`](/reference/react/useMemo) 让你缓存开销较大的计算结果。
*   [`useCallback`](/reference/react/useCallback) 让你在把函数定义向下传递给优化组件之前先将其缓存。  
function TodoList({ todos, tab, theme }) {  const visibleTodos = useMemo(() => filterTodos(todos, tab), [todos, tab]);  // ...}  
有时你无法跳过重新渲染，因为屏幕确实需要更新。那种情况下，你可以通过把必须同步的阻塞式更新（例如在输入框中输入）与不需要阻塞用户界面的非阻塞式更新（例如更新图表）分开来提升性能。  
要确定渲染优先级，可以使用以下 Hook 之一：  
*   [`useTransition`](/reference/react/useTransition) 让你把一次状态转换标记为非阻塞，并允许其他更新中断它。
*   [`useDeferredValue`](/reference/react/useDeferredValue) 让你推迟更新 UI 中非关键的部分，让其他部分先更新。

## 必填 Props

`<Image />` 组件需要以下属性。

### src

必须是以下两者之一：

-   静态导入的图像文件
-   路径字符串。它可以是绝对外部 URL，也可以是取决于 loader prop 或 loader 配置的内部路径。

使用默认 loader 时，还需考虑源图像的以下事项：

-   当 src 是外部 URL 时，你还必须配置 remotePatterns
-   当 src 是动图或未知格式（JPEG、PNG、WebP、AVIF、GIF、TIFF）时，图像将原样提供
-   当 src 是 SVG 格式时，除非启用 `unoptimized` 或 `dangerouslyAllowSVG`，否则会被阻止

### width

`width` 属性可以表示_渲染后_的宽度，也可以表示_原始_宽度（以像素为单位），具体取决于 `layout` 和 `sizes` 属性。

当使用 `layout="intrinsic"` 或 `layout="fixed"` 时，`width` 属性表示_渲染后_的宽度（以像素为单位），因此它会影响图像显示的大小。

当使用 `layout="responsive"`、`layout="fill"` 时，`width` 属性表示_原始_宽度（以像素为单位），因此它只会影响宽高比。

除静态导入的图像以及使用 `layout="fill"` 的图像之外，`width` 属性是必填的。

### height

`height` 属性可以表示_渲染后_的高度，也可以表示_原始_高度（以像素为单位），具体取决于 `layout` 和 `sizes` 属性。

当使用 `layout="intrinsic"` 或 `layout="fixed"` 时，`height` 属性表示_渲染后_的高度（以像素为单位），因此它会影响图像显示的大小。

当使用 `layout="responsive"`、`layout="fill"` 时，`height` 属性表示_原始_高度（以像素为单位），因此它只会影响宽高比。

除静态导入的图像以及使用 `layout="fill"` 的图像之外，`height` 属性是必填的。

### layout

| `layout` | 行为 | `srcSet` | `sizes` | 有 wrapper 和 sizer |
| --- | --- | --- | --- | --- |

在上方的沙盒中，输入框只会更新 `message` 状态变量。从用户的角度看，这不应该影响聊天连接。然而，每当你更新 `message` 时，你的组件就会重新渲染。当组件重新渲染时，其中的代码会从头重新运行一遍。  
`ChatRoom` 组件每次重新渲染时，都会从头创建一个新的 `options` 对象。React 看到 `options` 对象与上一次渲染时创建的 `options` 对象是_不同的对象_。这就是为什么它会重新同步你的 Effect（它依赖于 `options`），于是你每敲一个字聊天就会重新连接。  
**这个问题只影响对象和函数。在 JavaScript 中，每个新创建的对象和函数都被视为与其他所有对象和函数都不同。即使它们内部的内容可能相同也不要紧！**  
// 第一次渲染期间const options1 = { serverUrl: 'https://localhost:1234', roomId: 'music' };// 下一次渲染期间const options2 = { serverUrl: 'https://localhost:1234', roomId: 'music' };// 这是两个不同的对象！console.log(Object.is(options1, options2)); // false  
**对象和函数作为依赖项，会让你的 Effect 比实际需要更频繁地重新同步。**  
因此，只要有可能，你就应当尽量避免把对象和函数作为 Effect 的依赖项。相反，试着把它们移到组件外部、Effect 内部，或者从中提取出原始值。

# AI SDK 概览

AI SDK 是一个 TypeScript 工具包，旨在简化使用 React、Next.js、Vue、Svelte 和 Node.js 等各种框架构建 AI 驱动应用的流程。它提供了一套统一的 API 来操作不同的 AI 模型，让把 AI 能力集成进你的应用变得更容易。

AI SDK 的关键组件包括：

1. **AI SDK Core**：它提供了一种标准化的方式，用于与大型语言模型（LLM）生成文本、结构化对象以及工具调用。
2. **AI SDK UI**：它提供与框架无关的 hooks，用于构建聊天界面和生成式用户界面。

## 语言模型中间件

语言模型中间件是 AI SDK 中的一项实验性功能，它允许你通过拦截并修改对语言模型的调用来增强语言模型的行为。它可以用于以与语言模型无关的方式添加护栏、检索增强生成（RAG）、缓存和日志等能力。

下面是一个日志中间件的示例，它会记录一次语言模型调用的参数和生成的文本：

import type {
Experimental_LanguageModelV1Middleware as LanguageModelV1Middleware,
LanguageModelV1StreamPart,
} from 'ai';

export const loggingMiddleware: LanguageModelV1Middleware = {
wrapGenerate: async ({ doGenerate, params }) => {
  console.log('doGenerate called');
  console.log(`params: ${JSON.stringify(params, null, 2)}`);

  const result = await doGenerate();

  console.log('doGenerate finished');
  console.log(`generated text: ${result.text}`);

  return result;
},

wrapStream: async ({ doStream, params }) => {
  console.log('doStream called');
  console.log(`params: ${JSON.stringify(params, null, 2)}`);

  const { stream, ...rest } = await doStream();

  let generatedText = '';

  const transformStream = new TransformStream<
    LanguageModelV1StreamPart,
    LanguageModelV1StreamPart
  >({
    transform(chunk, controller) {
      if (chunk.type === 'text-delta') {
        generatedText += chunk.textDelta;
      }

      controller.enqueue(chunk);
    },

    flush() {
      console.log('doStream finished');
      console.log(`generated text: ${generatedText}`);
    },
  });

  return {
    stream: stream.pipeThrough(transformStream),
    ...rest,
  };
},
};

// 使用示例

import { openai } from '@ai-sdk/openai';

const wrappedModel = wrapLanguageModel({
model: openai('gpt-4o'),
middleware: loggingMiddleware,
});

const result = streamText({
model: wrappedModel,
prompt: 'Explain the concept of middleware in software development.',
});

for await (const chunk of result.textStream) {
console.log(chunk);
}

        export function useStopwatch(initialTime: number = 0) {
        const [time, setTime] = useState(initialTime);
        const [isRunning, setIsRunning] = useState(false);
        const intervalRef = useRef<NodeJS.Timeout | null>(null);

        const start = useCallback(() => {
          if (!isRunning) {
            setIsRunning(true);
            const startTime = Date.now() - time;
            intervalRef.current = setInterval(() => {
              setTime(Date.now() - startTime);
            }, 10);
          }

          if (isRunning && intervalRef.current) {
            clearInterval(intervalRef.current);
            setIsRunning(false);
          }
        }, [isRunning]);

        const reset = useCallback(() => {
          if (intervalRef.current) {
            clearInterval(intervalRef.current);
          }
          setTime(0);
          setIsRunning(false);
        }, []);

        return { time, isRunning, start, pause, reset };
        }
