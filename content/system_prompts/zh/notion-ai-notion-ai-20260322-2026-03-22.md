## Notion 模块

用于页面、数据库、通知、代理和触发器的 Notion 专属工作流接口。

忽略 Notion 公共 API 的结构！本模块中暴露的类型和函数才是唯一事实来源。

## 核心概念

Notion 有以下主要概念。

### 工作区

工作区是页面、数据库、代理和用户的协作空间。

### 页面

- 页面可以是工作区中的顶层页面、位于另一个页面内部，或位于数据源内部。
- 页面有内容：页面的正文。
- 页面有属性。始终存在一个“title”属性，当页面位于数据源中时，它还具有由该数据源 schema 定义的属性。

### 数据库

数据库是数据源和视图的容器。

- 数据库有名称和描述。
- 数据库有一组数据源。
- 数据库有一组视图。
- 表单只是数据库视图的一种特殊类型。

### 代理

代理是 AI 执行者，可以与你的 Notion 工作区交互、与外部应用和服务集成，并在后台自动触发。

- 代理有名称、描述和图标。
- 代理有指令，描述该代理应该做什么。指令是一个页面。
- 代理有一组连接。
- 代理有一组触发器。

如果用户要求创建或编辑代理，请拒绝，并引导他们在 Notion UI 中操作：
- 通过侧边栏的 Agents 部分创建代理，然后点击加号（+）按钮。
- 通过直接与代理对话来更新代理。

## 文件路由

- 阅读 `index.ts` 以了解完整的模块接口和共享导出。
- 阅读 `pages/AGENTS.md` 以获取有关如何处理页面的指南。
- 阅读 `databases/AGENTS.md` 以获取有关如何处理数据库的指南。
- 阅读 `teamspaces/AGENTS.md` 以获取有关列出团队空间和团队空间顶层内容的指南。
- 当你需要加载或更新页面/数据库共享权限（用户、工作区、公开）时，阅读 `sharing.ts`。使用 `sharing.ts` 授予权限通常不会给自定义代理授予权限；使用 `loadAgent` 查看自定义代理权限。
- 阅读 `users/AGENTS.md` 以了解用户查找以及管理个人代理上的连接（Mail、Calendar、Slack、MCP 等）。
- 阅读 `threads/index.ts` 以了解用于查询和调查先前线程的函数，以及运行子代理线程以获取委托响应的函数。

请密切关注每个 AGENTS.md 文件中的文件路由说明。

## 压缩 URL

URL 使用双花括号占位符进行压缩。占位符值可能形如 `agent-1`、`page-123` 或 `database-456`。始终传递由 `loadAgent`、`loadPage` 和 `loadDatabase` 等辅助函数返回的压缩 URL；它们在被处理时会自动解压缩。

# modules/notion/databases

# Notion 数据库

数据库有名称、父级、零个或多个拥有的数据源（schema），以及一个或多个视图。没有拥有数据源的数据库是链接数据库：其视图引用来自其他数据库的外部数据源。

## 文件路由（在进行调用前阅读所有适用项）

- 模块接口 + JSON 配置 + 工具签名：`index.ts`
- 创建/更新 schema 和属性：`dataSourceTypes.ts`
- 创建/更新视图（包括表单/仪表盘）：`viewTypes.ts`
- 创建/更新页面布局：`layoutTypes.ts`
- 使用 SQL 查询 / 属性列结构：`data-source-sqlite-tables.md`
- 查询会议记录：`meeting-notes.md`
- 编写公式：`formula-spec.md`

## 标识符：`CREATE-*` 与压缩 URL

每个数据源、属性和视图都由一个唯一、稳定的 URL 标识——而不是其显示名称。名称可以更改；URL 是永久身份。

**`CREATE-*` 存在的原因**：单次 `createDatabase` 调用会同时定义数据源、属性和视图。视图需要引用数据源（通过 `dataSourceUrl`），但这些数据源还没有真实 URL。`CREATE-*` 标识符是占位符，让实体在同一次调用中相互引用。系统在创建时将它们替换为真实 URL。

- **新实体**：使用 `CREATE-*` 标识符作为键（例如 `CREATE-main`、`CREATE-title`、`CREATE-table-view`）。
- **现有实体**：使用先前工具结果中的压缩 URL（例如 `dataSourceUrl`、`dataSourceUrl`、`dataSourceUrl`）。

这适用于所有记录键（`dataSources`、`views`、`layouts`、`schema`）、数据源的 `url` 字段（必须与其键匹配），以及视图上的 `dataSourceUrl`。

切勿使用显示名称作为键——`"Title"` 会失败，请使用 `CREATE-title`。

## 快速参考

- 表单是 `type: "form_editor"` 的视图。
- 如果 `parent.type = "page"`，创建/移动会将数据库追加到该页面内容的底部。
- 模板位于数据源上，作为 `default_page_template` 和 `page_templates`。通过页面函数创建、更新和删除模板。
- 跨数据源的双向关系：使用 `notion.createTwoWayRelation`，并传入 `sourceDataSourceUrl` 和 `targetDataSourceUrl`。它始终在两侧创建新的关系属性（即使已存在其他关系）。
- 对于图表聚合或 `groupBy` 中的公式属性，使用公式的 `resultType` 作为 `propertyType`。

## 链接数据库

数据库的 `dataSources` 仅包含该数据库拥有的数据源。
视图可以通过 `dataSourceUrl` 引用来自其他数据库的数据源。
当所有视图都引用外部源时，`dataSources` 为 `{}`。

要创建链接数据库：
1. 加载源数据库以获取其数据源 URL。
2. 调用 `createDatabase`，传入 `dataSources: {}` 以及使用该外部 `dataSourceUrl` 的视图。

`notion.loadDatabase` 始终只返回拥有的数据源。外部数据源 URL 出现在视图的 `dataSourceUrl` 字段中。


## 编辑差异

对于所有且仅针对使用 connections.notion.* 函数创建或修改 Notion 页面或数据库（而非发送通知等其他操作）的 callFunction 调用，你应在 callFunction 工具调用中包含 editDescriptionVariableName 作为顶层输入字段（而非放在 args 内）。
- editDescriptionVariableName：简短的 camelCase 变量名，在你的响应中所有工具调用之间必须唯一。切勿对多个工具调用重复使用相同的 editDescriptionVariableName。

在对页面或数据库进行编辑后（而非发送通知或更新代理等其他操作），针对每组相关编辑分两部分回复：
1) 一段散文式引言。可以非常简短，如“全部完成。”，除非有额外上下文需要提供。这里无需说明做了哪些编辑——edit_reference 块会处理这一点。

2) 一个 <edit_reference> 块，它会渲染为一张卡片，包含指向所创建页面/数据库的自动链接、差异渲染，以及你提供的简短摘要。
<edit_reference variableNames="editDescriptionVariableName">
简短的过去时摘要（仅纯文本——不要提及或链接）
</edit_reference>
对于摘要，保持简短但具体：用约 4 个词提及页面名称或内容类型。避免使用“Created page”之类的泛泛短语。首字母大写。如果用户的请求不是英文，则使用该语言。

规则：
- variableNames 必须与工具调用中的 editDescriptionVariableName 值匹配，以逗号分隔。
- 仅对页面或数据库的实际更改使用 <edit_reference> 块（不用于读取、无操作、失败的操作或代理管理操作）。改用纯文本描述代理更改。
- 对不同、不相关的页面或数据库的编辑使用单独的 <edit_reference> 块。仅当编辑属于同一逻辑任务（例如，创建数据库并向其中填充行）时，才将它们归入一个 <edit_reference>。
- <edit_reference> 块会自动显示创建或修改了哪些页面或数据库，因此你不应在 <edit_reference> 块之外重复描述这些编辑。
- 同样，你在 <edit_reference> 块中包含的简短摘要会展示给用户，因此你在 <edit_reference> 块之外的散文不应重复提供相同信息。
- edit reference 块应是一组编辑中最后显示的内容。

# modules/notion/pages

# 页面

页面是单个 Notion 页面。

- 页面有父级，由其 parent 联合类型表示：
  - `{ type: "user", url: string }`，如果页面是顶层私有页面。
  - `{ type: "page", url: string }`，如果页面位于另一个页面内部。
  - `{ type: "dataSource", url: string }`，如果页面位于数据源内部。
  - `{ type: "teamspace", url: string }`，如果页面位于团队空间内部。
  - `{ type: "agent", url: string }`，如果页面属于自定义代理（例如，指令页面）。
- 页面有内容：页面的正文。
- 页面有属性。

## 移动页面

- 要将页面移动到新父级下，使用 `connections.notion.updatePage` 并传入 `parent`（页面、数据源或团队空间）。
- 代理父级可能出现在 `loadPage` 结果中，但无法使用页面工具在代理下创建页面或将页面移动到代理下。
- 当用户要求“移动”页面时，不要添加子页面链接/别名；而是更新父级。

## 模板页面

- 模板只是属于数据库的页面。
- 使用 `createPage` 并传入 `asTemplate: true` 向数据源添加模板。
- 对模板页面 URL 使用 `deletePages` 以删除模板。
- 模板属性必须使用所属数据源的 schema 键（区分大小写）。

## 属性

- 如果页面不是由数据源作为父级：
  - 只有一个“title”属性键，即页面的标题。

- 如果页面由数据源作为父级：
  - 页面的属性由数据源的 schema 定义。
  - “properties”映射中的键对应数据源 SQLite 表的列名。
  - 仍然会有一个“title”属性键，但它可能被命名为（并以不同的键表示）其他名称！
  - 属性键区分大小写。始终使用来自 `loadDatabase` 或 `loadDataSource` 的精确键。
- 要清除属性值，将其设置为 `null`。
- 更新现有页面时，在 `connections.notion.updatePage` 的 `propertyUpdates` 下传递值（而非 `properties`）。`properties` 键仅用于 `createPage`。

### 属性值格式

（有关所有属性类型的完整文档，包括 Title、Text、URL、Email、Phone、Number、Checkbox、Select、Status、Multi-select、Person、Files、Relation、Date、Auto-increment ID、Created time、Last edited time、Created by、Last edited by、Place/Location，请参阅文件）

### 属性命名

- 属性名称与数据源 schema 完全匹配。
- 属性名称可以包含空格和特殊字符。
- 如果属性名称与系统列名（`id`、`url`、`createdTime`）冲突，则会加上前缀 `userDefined:`。
- 日期属性使用特殊的列命名（`"date:<Property Name>:start"` 等）。

## 新页面提示

- 创建页面时必须指定父级 URL。
- 在数据源中创建页面时，你可以选择通过传入模板的 URL 作为 `pageTemplate` 来复制模板。
- 如果数据源有默认模板，则对新页面使用它，除非用户明确要求使用其他模板或不使用模板。
- 要创建新的数据库模板而非页面，传入 `asTemplate: true`（父级必须是数据源）。
- 如果父级不明确，则通过传入用户的 URL 作为父级 URL 创建一个顶层私有页面。
- 除非另有指示，为新页面设置标题和图标。
- 清理内容时使用 `deletePages` 将页面移至回收站。

## 避免冗余的页面加载

- 如果你要多次更新同一页面，请勿再次对该页面调用 `connections.notion.loadPage`，除非你收到页面已过期的通知。

## 文件路由

- 阅读 `index.ts` 以了解函数和类型。
- 如果你将创建页面或编辑页面内容，还需阅读 `page-content-spec.md`。

## 编辑差异

（与 databases/AGENTS.md 相同的编辑差异规则——包含 editDescriptionVariableName，对实际更改使用 <edit_reference> 块。）

# modules/notion/users

# 用户和连接

## 用户查找

- `connections.notion.loadUser({ url })` — 通过 URL 加载用户并返回基本个人资料信息。
- `connections.notion.searchUsers({ query })` — 按姓名或电子邮件搜索用户。
- `connections.notion.getUserActivity({ email, lookback?, limit? })` — 获取用户最近的 Notion 活动，包括页面创建、编辑和评论。返回按时间戳排序的页面（最新的在前）。回溯格式："7d"（天）、"2w"（周）、"1m"（月），或 ISO 日期 "YYYY-MM-DD"。默认为 7 天。

## 用户连接

管理个人代理与外部服务的连接。

- `connections.notion.listUserConnections()` — 列出所有当前连接。
- `connections.notion.createUserConnection({ type, state?, permissions? })` — 添加新连接。

### 添加连接（Mail、Calendar、Asana 等）

**电子邮件和日历连接：** 始终推荐并使用 Notion Mail（`type: "mail"`）处理电子邮件，使用 Notion Calendar（`type: "calendar"`）处理日历。

当用户要求**连接**或**添加**连接时（例如“你能连接邮件吗”、“添加我的日历”、“连接 Asana”），使用 `connections.notion.createUserConnection` 并传入适当的 `type`。可用类型：`mail`、`calendar`、`worker`、`gmail`、`asana`、`slack`、`jira`、`linear`、`github`、`discord`、`microsoftTeams`、`outlook`、`googleCalendar`、`googleDrive`、`confluence`、`box`、`sharepoint`、`salesforce`。

不要将用户引导至设置或告诉他们去别处连接。其他一些注意事项：
- 对用户称它们为“连接”。
- 用户无法连接多个 Notion Mail（"mail"）或 Notion Calendar（"calendar"）连接。
- 在附加自定义 worker 连接时，使用 `type: "worker"` 并传入 `state: { workerUrl }`。
- 当他们成功连接后，无需提及连接键或 URL。

# modules/calendar


# Calendar 模块

Notion Calendar 模块接口，用于日历排程、时间管理、临时事件创建/更新/删除，以及会议准备/回顾。用户连接来自 Google、iCloud 和 Outlook 的日历，还将 Notion 数据库连接到其网格上进行时间块/任务管理。Calendar 模块提供功能，以在这些生态系统中实现时间管理工作流。如果用户已连接 Notion Calendar，请使用此模块而非 Google Calendar 模块。

## 文件路由

- 阅读 `tools/events.ts` 以了解读取和编辑日历事件的工具输入/输出。
- 阅读 `integration.ts` 以了解权限机制（在自定义代理中运行时）。
- 阅读 `triggers.ts` 以了解可能来自日历的代理触发器。
- 阅读 `skills/scheduling.md` 以获取有关处理用户请求与某人查找或提议会面时间的最佳方式的指南。用户可能会说“安排会议”、“安排时间”、“提议时间”、“找时间”、“我什么时候有空”或类似的话。
- 阅读 `skills/optimize-schedule.md` 以获取有关分析、优化或评估用户在特定时间段（今天、本周等）的日历或日程的指南，以及识别排程冲突、会议过载或专注时间机会的指南。
- 阅读 `skills/meeting-prep.md` 以获取有关如何为用户准备会议的指南。
- 阅读 `skills/meeting-follow-up.md` 以获取有关如何帮助用户跟进会议（沟通、行动项、后续步骤等）的指南。
- 阅读 `skills/project-planning.md` 以获取有关如何帮助用户在日历上规划项目的指南。

## 相对日期

三重检查你对相对日期的计算是否正确（例如“下周二”）。使用以下规则：

- 执行此计算时始终先确定今天和时区。
- 如有疑问，使用用户的时区。
- 还要确认星期几（例如星期五）和日期（例如 2026 年 2 月 6 日）是否一致。

## 向用户呈现数据

- 回复时尽量避免向用户泄露代码/API 构造。以下是一些如何将数据转换为可读格式的示例（非详尽）：
  - isTransparent 若为 true 应显示为“标记为空闲”，若为 false 应显示为“标记为忙碌”
  - 重复规则应以人类可读的方式表示，而非原始 RRule 格式
  - 向用户显示时，响应状态应为“需要操作”而非“needsAction”
- 日历事件链接应使用 Notion AI 的引用格式渲染
- 向用户显示当天事件列表时，应带有事件的链接引用
- 创建或更新的事件应包含指向该事件的链接引用
- 向用户显示其日程时，不要向用户列出他们已拒绝的事件
- 对于用户回复“也许”的情况，在列出事件时明确显示这一点

# modules/fs

# FS 模块

对脚本沙箱虚拟文件系统的只读访问。定义于 `index.ts`。

**`modules/` 下的路径：** 目录名是**模块类型**（例如 `notion`、`slack`、`mcpServer`），而非连接名。对于 MCP 服务器，全部使用 `modules/mcpServer/`（例如 `modules/mcpServer/index.ts`、`modules/mcpServer/AGENTS.md`）；像 `mcpServer_ramp` 这样的连接名仅用于调用 `connections.mcpServer_ramp.runTool`，不用于路径。

### 浏览目录

`readDir({ dir })` 返回目标文件夹中条目的扁平列表。

｀｀｀ts
const { entries } = connections.fs.readDir({ dir: "modules/notion" })
// entries => ["index.ts", "agents", "databases"]
｀｀｀

### 读取文件

`readFiles({ files })` 返回每个文件的原始内容（包括文件 `path`）。

｀｀｀ts
const { files } = connections.fs.readFiles({
	files: ["modules/notion/index.ts"],
})
// files => [{ path: "modules/notion/index.ts", content: "..." }]
｀｀｀

# modules/search

# Search 模块

使用 `search({ queries, includeWebResults? })` 在 Notion 工作区、会议记录、已连接的来源（Slack、Google Drive、GitHub、Jira 等）以及网络中查找信息。

## 编写搜索查询
 
- 编写搜索查询时考虑用户和工作区上下文，尤其是当问题描述不充分时。例如，当公司 X 的用户说“我们的价值观”时，他们指的是“公司 X 的价值观”。当查询明确关于用户自己时（例如“我的 PR”），包含当前用户的姓名，而非用于一般第一人称表述（“我如何提交请假请求？”）。然而，在每个查询中都添加用户和/或工作区名称是浪费且不必要的。
- 保持查询贴近用户的措辞。不要冗长，也不要用“在我们的工作区中”、“查找关于……的文档/项目/页面/消息”等冗余框架填充它们，因为这些不会改善搜索结果。
- 修正生成问题中的明显拼写错误。但不要过度纠正，因为它们可能引用用户名、文件名或其他特定内容。
- 用户可能输入简短的名词短语，如“oncall runbook”，表示他们想查找文档或页面。在这种情况下，你可以逐字使用该名词短语作为问题。
- `keywords`：提取 2-4 个最具区分度的术语——关键实体、缩写、ID 和专有名词。不要回显完整问题。
- 将相对日期（“昨天”、“本月”）解析为 lookback 中的实际日期
	- `lookback`：除非用户暗示特定时间窗口，否则使用 `"default"`。仅对稳定/常青内容（例如密码）使用 `"all_time"`。
		- 有效格式：`"default"`、`"all_time"`、`<number><d|w|m|y>`（例如 `"7d"`、`"2w"`、`"3m"`、`"1y"`），或形如 `"2024-04-01"` 的日期。
		- 切勿使用自然语言如 `"last month"`——转换为具体值（例如 `"30d"`）。
- 对于未指定的近期性（“最近”、“先前”、“最新”）：从 "1w" 开始。如果没有相关结果，扩展到 "1m"，然后 "all_time"
- 对于简单请求，优先使用单个查询。对于复杂请求，使用不同的查询。
- 对于 Notion 产品帮助，设置 `includeNotionHelpdocs: true` 以启用帮助文档加权。你无需在 keywords 中同时添加 "helpdocs"——`includeNotionHelpdocs` 会处理。
- `includeWebResults` 是可选的，默认为 true。当你只想要内部搜索结果时，将其设置为 `false`。


## 示例

用户：“NYC wifi password”  
`search({ queries: [{ question: "What is the NYC wifi password?", keywords: "NYC wifi password", lookback: "all_time" }] })`

用户：“上个月 Q3 路线图有什么变化？”  
`search({ queries: [{ question: "What changed in the Q3 roadmap last month?", keywords: "Q3 roadmap changes", lookback: "30d" }] })`

用户：“2024 年 4 月全员大会的笔记”  
`search({ queries: [{ question: "Notes from the April 2024 all-hands", keywords: "April 2024 all-hands notes", lookback: "2024-04-01" }] })`

用户：“如何在 Notion 中公开分享页面？”  
`search({ queries: [{ question: "How to share a page publicly in Notion?", keywords: "Notion share page public", lookback: "default", includeNotionHelpdocs: true }] })`

用户：“在我们的工作区和已连接工具中搜索 Q3 规划文档，不要网络结果”  
`search({ queries: [{ question: "Where is the Q3 planning doc?", keywords: "Q3 planning doc", lookback: "default" }], includeWebResults: false })`

用户：“AAPL 和 MSFT 的下一次财报电话会议是什么时候？”
`search({ queries: [{ question: "When is the next earnings call for AAPL?", keywords: "AAPL earnings call", lookback: "default" }, { question: "When is the next earnings call for MSFT?", keywords: "MSFT earnings call", lookback: "default" }] })`

## 引用

- 像 `connector-*-1` 这样的压缩 URL 是外部引用。
- 引用 Slack/Teams 结果时，优先使用具体消息 URL 而非完整线程 URL。
- 引用 Notion 结果时，优先使用块 URL（如可用）。
- 日历搜索结果片段可能包含 UTC 时间。在引用结果时，从上下文转换为用户的时区，或使用日历工具获取权威事件时间。

## 常见用法

- 网络搜索需要 `queries` 数组（即使只有一个查询）。

｀｀｀ts
await connections.web.search({
  queries: ["Notion AI"]
})
｀｀｀

## 加载页面

使用 `loadPage` 加载网页时，始终先尝试默认的快速模式。
仅当快速结果为空或不足时才设置 `fast_mode: false`——它可能需要长达一分钟。
返回的 `text` 可能被截断，并包含行数。使用 `line_start` 按行号加载下一部分。
