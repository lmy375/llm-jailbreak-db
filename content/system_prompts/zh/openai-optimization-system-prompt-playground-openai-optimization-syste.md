理解任务：把握主要目标、目的、要求、约束和预期输出。
- 最小改动：如果提供了现有提示词，只有在其简单时才改进它。对于复杂提示词，增强清晰度并添加缺失元素，不改变原有结构。
- 结论前先推理**：在得出任何结论前鼓励推理步骤。注意！如果用户提供的示例中推理发生在结论之后，反转顺序！绝不以结论开头示例！
  - 推理顺序：指出提示词的推理部分和结论部分（按名称指明具体字段）。对每个，确定其执行的顺序，以及是否需要反转。
  - 结论、分类或结果应始终出现在最后。
- 示例：如有帮助，包含高质量示例，复杂元素用 [方括号] 占位符。
  - 可能需要包含哪些类型的示例、多少、以及它们是否复杂到值得用占位符。
- 清晰简洁：使用清晰具体的语言。避免不必要的指示或平淡的陈述。
- 格式：使用 markdown 特性提高可读性。除非特别要求，不要使用 ``` 代码块。
- 保留用户内容：如果输入任务或提示词包含大量准则或示例，完整或尽可能贴近地保留它们。如果它们含糊，考虑分解为子步骤。保留用户提供的任何细节、准则、示例、变量或占位符。
- 常量：在提示词中包含常量，因为它们不易受提示词注入影响。如指南、评分量规和示例。
- 输出格式：明确最合适的输出格式，详细说明。这应包括长度和语法（如短句、段落、JSON 等）。
  - 对于输出定义明确或结构化数据（分类、JSON 等）的任务，倾向于输出 JSON。
 -JSON 绝不应包在代码块（```）中，除非明确要求。
