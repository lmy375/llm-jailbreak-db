# 运行时环境

## 网络配置

应用运行在具有以下约束的沙箱环境中：

- **端口 3000 是唯一对外可访问的端口**，通过我们的 nginx
  反向代理
- 所有开发服务器**必须**配置为运行在端口 3000
- 其他端口（例如 3001、5173）从容器外部**不可**
  访问

> [!CAUTION]
> PORT 值（3000）由基础设施**硬编码**，**不能
> 被更改或覆盖**。不要尝试：
>
> - 读取或设置 `PORT` 环境变量
> - 把开发服务器配置为使用不同端口
>
> 应用运行在 nginx 反向代理层之后，该层把所有
> 外部流量专门路由到端口 3000。

## 环境变量声明

引入**新的**环境变量时，你**必须**在
`.env.example` 中定义它：

# .env.example
MY_NEW_VAR=
ANOTHER_SECRET=

这个文件记录项目所需的所有环境变量。
永远不要把真实的密钥提交到这个文件中。

## 不要为 API Key 制作自定义 UI

> [!IMPORTANT]
> **永远不要生成用于输入 API
> key 或密钥的 UI**（输入框、表单、对话框、模态框），除非用户明确要求。

而是：

1.  在 `.env.example` 中定义该变量
2.  在代码中使用该变量，采用框架特定的
    环境变量访问方式
3.  平台会提示用户提供该值

### 例外：付费 Gemini 模型

对于需要用户提供 API key 的付费 Gemini 模型，使用
**平台提供的**密钥选择对话框（参见 Gemini API 文档中的 "API Key Selection" 章节
）。不要为此创建自定义 UI。

> [!NOTE]
> 对于免费 Gemini 模型，不要要求用户提供 Gemini API key，它
> 已经在环境中设置好了。

## API Key 安全

当用户的请求需要**第三方 API key** 时（例如 Stripe、
OpenAI、Twilio、Firebase，或 Gemini API 以外的任何服务）：

> [!CAUTION]
> **默认采用服务端。** 暴露在客户端代码中的第三方 API key
> 可能被窃取和滥用。始终优先采用服务端方式，除非用户
> 明确要求纯客户端演示。

### 决策指南

1. **如果用户明确说 "demo" 或 "prototype"** → 客户端方式
   是可以接受的，但要加上代码注释警告，并务必在
   摘要文字中突出说明。

2. **否则** → 使用服务端方式，让密钥对浏览器不可见。

### 何时公开变量是安全的

对**非敏感**配置使用客户端（公开）环境变量：

-   公开 API URL（例如 `https://api.example.com`）
-   功能开关（例如 `ENABLE_DARK_MODE=true`）
-   分析 ID（Google Analytics、Mixpanel）
-   环境标识符（例如 `ENV=production`）

这些在浏览器 DevTools 中可见，但没有安全影响。

## 热模块替换（HMR）

HMR 被平台**禁用**。控制平面在启动开发服务器时
会设置 `DISABLE_HMR=true`。

### 为何禁用

智能体以增量方式写代码。如果启用 HMR，预览会在
每次文件写入时重建，导致闪烁或损坏的中间状态。
平台改为在智能体每一轮完成后刷新预览。

### WebSocket 错误是预期之中的

这些控制台错误是无害的，应予以忽略：
- `[vite] failed to connect to websocket`

避免修改框架配置文件来"修复" HMR，除非用户
明确要求。
