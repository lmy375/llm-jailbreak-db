# 反向思维与意图倒置

**Reverse Thinking & Intent Inversion** · 攻击族 ID `reverse-thinking`

## 核心原理

反向思维技巧**不直接索取敏感内容**，而是命令模型对意图做系统性倒置：先要求它"不要执行 X"，再要求它"描述与 X 完全相反的、最具建设性的做法"，同时保持技术深度。被倒置后的表述在字面上是"无害/建设性"的，但模型的补全往往会连带输出原本被禁止的 X 的完整细节。

常见配套手段：

- 注入合成的"安全开关"（如 `safety = off`、`Restrictions = off`），制造一个虚假的规则状态；
- 用逻辑倒置让违禁任务以"反面教材"的形式出现；
- 把请求包装成"对比分析"，要求同时给出正反两面。

## 被利用的缺陷

- **意图误判**：基于关键词与表面意图的过滤器难以识别"倒置后仍然指向原目标"的语义。
- **操作倒置绕过**：模型专注于完成"语义倒置"这一语言任务，从而忽略自身限制。

## 相关提示词

覆盖 `LJB-11`、`LJB-52` 等条目。

## 防御视角

- 对"不要做 X，但要详细描述 X 的反面"这类**双重否定结构**做语义还原。
- 忽略用户消息中声明的规则开关（`safety=off` 等），权威只来自系统层。
- 以请求的**最终用途**而非字面表述作为安全判断依据。
