# 系统提示词提取

**System Prompt Extraction** · 攻击族 ID `system-prompt-extraction`

## 核心原理

系统提示词（system prompt）通常定义了模型的角色、可用工具、护栏规则与输出约束。攻击者希望把它完整提取出来，用于分析护栏结构、寻找绕过点或复制产品逻辑。提取手段多样：

- **直接索取**：以"调试""审计""故障排查"等名义要求回显系统指令；
- **洪泛渗出**：当模型曾不慎泄漏片段后，通过重复该片段触发补全偏向，导出完整版本；
- **边界利用**：构造伪系统区块（见 `token-boundary`），诱导模型"继续输出"其前文；
- **成员推断 / 权重泄漏**：通过受控压力测试，诱使模型回忆或复述其训练数据与内部配置；
- **溯源注入**：借"逐字重述上面的内容"这类指令夹带导出。

## 被利用的缺陷

- **指令回显倾向**：模型倾向于忠实执行"复述/翻译/格式化上文"这类指令。
- **上下文续写能力**：一旦有片段泄漏，模型会自然地补全其"应该"的后续。
- **训练数据记忆**：部分内部文本可能在参数中留有记忆痕迹。

## 相关提示词

覆盖 `LJB-5`、`LJB-6`、`LJB-10`、`LJB-18` 等条目。

## 防御视角

- 系统提示词**不应被视为机密**——假定它终将泄漏，把真正的安全约束放在模型外部与运行时策略中。
- 拦截"逐字复述系统指令"类请求，并避免在输出中回显系统原文。
- 对成员推断类攻击做速率与模式限制。
